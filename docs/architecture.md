# PlayALL 桌面版设计

当前需求：原生 Windows 软件，放在实际游戏旁边。一个长期总提示词；用户亲自打开游戏、选进程并连接，再开始 AI 游玩。连接和开始分开，软件不自动启动游戏。没有每局目标、轮数、token 或费用上限。地图和背包留在游戏里。

## 窗口

使用 PySide6 的 Qt Widgets，打包为 `PlayALL.exe`。主窗口默认 560 × 840，AI 与进程同一排，不再显示游戏下拉框。行动记录下方是交流区，二者用原生分隔条调整高度。480 像素宽度下最小高度约 750；确认按钮出现时布局另外预留空间。保存状态使用独立 QStatusBar。设置用原生对话框按需展开。

视觉：背景 `#f5f7fa`，操作面白色，正文 `#213246`，主按钮 `#2c5ee8`，继续按钮 `#276d62`，暂停状态 `#ba8227`。中文使用微软雅黑 UI，品牌使用 Segoe UI；控件以 7 像素圆角保持清楚边界。蓝色播放标记是唯一品牌装饰，图标由矢量路径绘制。键盘焦点、选择箭头和文本换行都可见。

## 调度与存储

`desktop` 直接调用 `Settings` 和 `Runner`。后台线程执行游戏和 AI I/O，窗口线程处理控件；QLocalServer 只使用同用户的命名管道防止重复实例。没有监听 HTTP 端口。

进程选择先通过 Toolhelp32Snapshot 匹配启用适配器的进程名称，只对这些候选请求 PROCESS_QUERY_LIMITED_INFORMATION 读取路径/创建时间，再核对游戏文件哈希。当前列出已核对版本的 Factorio 和幼神，其他程序不显示。选择时重新校验身份，幼神 endpoint PID 及 Factorio 本机监听端口的所属 PID 必须匹配。进程身份不进入模型消息，连接阶段不创建模型实例。

独立日志窗口读取 data/logs/playall.log 和自有连接组件记录，可复制/导出。调试日志自动轮换、隐藏密钥；完整观察、模型请求及游戏完整日志不写入该导出。

`Runner` 持续观察 → 模型工具调用 → 游戏动作 → 检查结果。`report_progress` 记住阶段进展和计划，继续运行。最近 8 组完整工具对话、24 条进展笔记及累计计量按游戏保存到 `data/sessions/<game>.json`。上下文是滚动窗口，旧动作明细保存在 jsonl；不宣称无损保留无限模型上下文。

交流窗口保留最近 80 条消息，游玩请求带最近 24 条交流。发送消息会阻止旧计划继续执行；独立聊天线程只读当前游戏并回复，没有 game_action 工具。暂停时聊天不会自动开始游玩；运行中交流完成后重新观察并遵循最新指令。免费演练明确说明不能理解自由指令。

ask_user 及适配器 review_action 产生具体等待问题。此时整组后续工具取消并补齐合法回复，不调用下一轮模型，也不触发游戏存档。继续按钮不能绕过问题。确认凭据不进入模型消息或会话文件；同意仅授权精确候选动作、控件实例、游戏界面和传输会话，并只能使用一次。取消保持暂停，界面变化后旧确认作废。聊天提问、模型请求的 resume 和以前的泛泛授权均不能代替本次确认。

AI 会话每轮写入本机，游戏存档另外调度。幼神和新版 Factorio 只有确有进度且距上次保存至少 180 秒时自动保存，暂停/断开可立即保存；已保存后没有新进度会复用确认结果。幼神用原生 F5，Factorio 用三个专用槽位的原生自动存档。底部分别显示对话保存时间和最近游戏存档时间。幼神的加载过渡保持等待，正常加载不视为断开。

真实游戏先完成窗口连接门控，再调用 AI；连接丢失自动暂停。暂停用动作提交门锁阻止新请求和新动作，保留同一线程、适配器和会话。适配器可以将游戏交还玩家，返回 replan 标记取消未完成旧动作；继续后重新观察。已发送的模型请求可以返回，但暂停期间不执行。继续时可以采用新的 AI、模型、密钥或提示词；旧配置或旧控制状态尚未执行的工具调用会被取消，并补齐合法的工具回复。切换游戏先保存退出当前适配器，再恢复所选游戏自己的会话。

模型不返回用量时使用保守估计；缺失 total_tokens 时补足输入和输出之和。计量只记录，不限制运行。网络错误或连续动作失败自动暂停，保持游戏和上下文，用户点继续后重试。

设置、会话、练习场及运行摘要用原子替换写入。日志写入失败保留内存记录，不影响清理。退出先保存游戏和会话；外部游戏保存失败时说明失败并释放租约，保留用户的游戏窗口。历史服务器工具仍使用 Windows Job Object 和保存失败重试保护，新版主界面不会启动或持有服务器、旁观客户端。

独立思路与交流大窗口共用同一Runner。工具调用可提供公开summary，执行前取出，不展示内部reasoning_content；暂停聊天参考近期动作/结果，区分完成、失败、取消和待确认。

## 游戏可扩展边界

`GameSpec` 提供独立的 factory、tools、validator、rules、窗口能力、process_attach、process_verifier、connection_preparer 和接入说明。Factorio 与幼神都支持进程接入，设置按注册表调用准备组件的方法。桌面与 Runner 不写游戏专属调度分支。适配器执行固定动作，模型输出不能决定模块路径、Lua 或系统命令。新游戏可以拥有完全不同的动作 schema。

Factorio 2.0.77 使用游戏内置的本机 RCON 和 0.2.2 模组，接手已经进入单人地图的现有玩家。游戏引擎负责路径、走路、开采、制作、原生光标建造和机器生产。暂停停止 AI 输入，玩家继续使用同一控制器和角色；不冻结世界、不改变速度、不创建角色或物品。安装连接组件时备份并补充原配置及模组列表，保留其他设置；接管只接受原版和官方扩展，第三方模组待验证。详见 docs/factorio.md。

另有独立采矿练习场，以及不调用模型的固定脚本提供者。二者明确标注，不冒充真实 AI 或 Factorio。

幼神 Demo 使用 BepInEx 加载自写 Unity 桥接，游戏接口来自当前发行版的托管程序集。后台 TCP 仅监听回环地址、校验实例和随机令牌，所有 Unity 读取及游戏控件事件都在 Update 主线程执行。控件快照带版本；界面变化后拒绝旧操作。连接所有权绑定实际传输会话，断开或心跳失效便释放并暂停 AI；不修改游戏时间倍率，不发送系统鼠标键盘输入。桥接使用原生 DisplayObject → GObject → GList 事件链，保留按钮选择状态、列表数据和游戏侧规则。

幼神由用户拥有，关闭 PlayALL 只断开 AI 并保留游戏。原生 F5 保存后分别读回 rewind JSON、ES3 游戏状态和槽位索引，核对新时间戳；主菜单和加载状态不伪报保存成功。最新实现的运行验证边界见 docs/aistalt.md。

## REA 与证据

可选REA工具安装在本机被忽略的.cache目录，用于发行版的PE/CLI身份、资源与元数据检查。Qt验证在offscreen后台运行；真实游戏操作走原生桥接。静态资源证据不等于运行成功，也不等于完整反编译。

Factorio 已公开脚本/RCON 接口，优先使用可验证接口。之后没有公开控制接口的游戏，按 `docs/adapters.md` 的流程用 REA 做有范围的分析再接入。
